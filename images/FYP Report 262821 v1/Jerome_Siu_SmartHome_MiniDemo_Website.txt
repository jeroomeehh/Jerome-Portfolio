--------------------------------------------------------------------------------
Build An Internet of Things Application with Blockchain – Smart Home

1. PROJECT OVERVIEW & GOAL
--------------------------------------------------------------------------------
Goal:
To design and build a smart home application that combines Internet of Things
(IoT) technology with Blockchain, using a decentralised ledger to keep device
data secure, tamper-proof and transparent while delivering everyday home
automation.

Core Concept:
- IoT devices capture real-time data (e.g. temperature, device on/off state).
- Data travels over MQTT and is permanently recorded on an Ethereum blockchain.
- Smart contracts interpret the data and trigger predefined automated actions.
- A web dashboard lets users control devices, build "Scenes" and schedule routines.

--------------------------------------------------------------------------------
2. METHODOLOGY & TECH STACK
--------------------------------------------------------------------------------
Blockchain & Smart Contracts:
- Ethereum (smart-contract platform for tamper-proof data storage)
- Ganache v2.7.1 (local in-memory blockchain; 12-second block time to mirror
  Ethereum's Proof-of-Stake)
- Solidity v0.5.16, compiled with Truffle v5.11.5

Communication Layer:
- MQTT (lightweight publish/subscribe protocol ideal for IoT)
- Mosquitto v2.0.18 broker (port 1883 for MQTT, port 8081 for WebSockets)

Back-End (Python):
- MQTT–Smart Contract Bridge: stores incoming messages on-chain and publishes
  automated action messages.
- Scene Timer: checks scene schedules every whole minute and fires scene messages.

Front-End:
- HTML, CSS and JavaScript dashboard
- Web3.js for browser-to-Ethereum interaction
- Open-Meteo & OpenStreetMap APIs for live weather and location

IoT Hardware & Devices:
- ESP8266 Wi-Fi module driving a real dimmable LED bulb (Arduino firmware)
- Virtual sensors, heaters and lamps built in HTML/JavaScript for testing

3. SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------
Data Flow:
- IoT devices publish/subscribe to the Mosquitto MQTT broker.
- From the broker, data splits to two Python back-ends.
- Back-end 1 bridges MQTT to the blockchain, storing each device's messages in
  its own smart contract and checking them against automation rules.
- Back-end 2 acts as a timer handler, triggering scheduled scenes.
- The HTML/JavaScript front-end connects to both back-ends and to the blockchain,
  giving real-time control, history and scheduling.
- All data is stored on the Ganache blockchain.

4. SMART CONTRACT DESIGN
--------------------------------------------------------------------------------
Four Solidity contracts form the backbone of the system:

- SmartHome: central registry of every IoT device (name + contract address),
  with a deletion flag that preserves historical records.
- IoTdevice: one per device; logs timestamped messages and manages upper/lower
  thresholds that trigger automated alerts or actions.
- SceneList: manages the collection of scenes and their on/off timers, including
  repeat scheduling by day of the week.
- Scene: groups multiple devices and their control messages so they can be
  activated together with a single command.

--------------------------------------------------------------------------------
5. KEY FEATURES & DEMONSTRATION
--------------------------------------------------------------------------------
Core Features:
- User authentication for secure access.
- Add, control, remove and recover IoT devices.
- Device history logging on the blockchain (tamper-proof audit trail).
- Threshold-based automation (e.g. switch on the heater when temperature drops).
- Scene creation and management (control many devices at once).
- Countdown timers and scheduled/repeating scene activation.

Live Demonstration:
- A real ESP8266 LED bulb was connected to the system and dimmed / switched via
  the dashboard, with every command routed through the blockchain network.
- A virtual temperature sensor triggered an electric heater automatically once
  readings crossed the configured threshold.

6. TESTING & EVALUATION
--------------------------------------------------------------------------------
Unit Testing:
- Requirement-based test cases covering authentication, device management,
  control, automation, scenes and timers.
- Result: 100% pass (19/19 test cases produced the expected output).

Usability Testing:
- Participants completed all tasks (add devices, control, automate, build scenes,
  set timers) and found the interface intuitive and user-friendly.
- Feedback focused on visual polish (modern UI, brightness slider, on-screen
  clock, clearer timer setup) rather than functional faults.
